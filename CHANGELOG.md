# Changelog

All notable changes to `laravel-db-encryption` will be documented in this file.

## v1.1.0 `2026-11-07` - Security & Reliability Release 🔒

This release fixes security weaknesses in the v1.0 encryption format. **Upgrading is recommended for all users.** Existing data keeps working without changes. See [Upgrading from v1.0](README.md#upgrading-from-v10) to finish moving it to the new format.

### Security

- **Replaced AES-256-CBC with authenticated AES-256-GCM.** v1.0 ciphertext had no integrity check, so database-level changes to it went undetected. Tampered values now fail to decrypt. New values use a `v2:` prefixed format.
- **Fixed key derivation that reduced AES-256 to about 128 bits.** v1.0 passed a SHA-512 hex digest as the key, and OpenSSL used only its first 32 hex characters. Keys are now 256-bit values derived with HKDF-SHA256, with separate keys for encryption and search.
- **Search hashes are now keyed.** v1.0 stored an unkeyed SHA-256 of each value, so short values like Social Security numbers could be brute-forced from a stolen database without the key. `hash_index` now holds an HMAC-SHA256, scoped to the table and attribute, so equal values in different attributes no longer match.
- **Values are now bound to their row.** A ciphertext copied onto another record or attribute no longer decrypts, which stops someone with database write access from reading a value through their own account.
- **Model deletion now removes encrypted data.** v1.0 left it behind until `db-encrypt:prune` ran. Soft deletes keep the data until `forceDelete()`.
- Added `DB_ENCRYPT_LEGACY_SUPPORT`, to refuse the old format entirely once data is upgraded.
- `EncryptedAttributes` now hides `encrypted_value` and `hash_index` from arrays and JSON.
- Mass assignment and serialization guidance in the README corrected, including the need for `$hidden`.

### Added

- **Working key rotation.** `DB_ENCRYPT_PREVIOUS_KEYS` allows reads and searches with old keys, `db-encrypt:generate-key --rotate` moves the current key there, and `db-encrypt:re-encrypt` rewrites data with the new key.
- **Laravel 13 support**, alongside Laravel 12. Tested on PHP 8.3 and 8.5, with CI covering PHP 8.2 to 8.5.
- `db-encrypt:status` command, showing the configuration and how many legacy values remain.
- `db-encrypt:rename-table` command, for moving values to a new table name.
- `orWhereEncrypted()` and `whereEncryptedIn()` query scopes.
- `Model::withoutDecryption()`, to skip decryption queries when the values aren't needed.
- `--force` on `db-encrypt:re-encrypt`, and `--key` and `--batch` on `db-encrypt:prune`.
- `$context` parameters on `encrypt()`, `decrypt()`, `hash()` and `verify()`, plus `Encryptor::hashCandidates()`, `attributeContext()`, `searchContext()`, `isLegacyPayload()` and `legacySupportEnabled()`.
- `previous_keys` and `legacy_support` values in `Encryptor::getInfo()`.
- `EncryptedAttributes::payloadFor()` and `decryptValue()`.
- `.gitattributes`, to keep tests and development files out of Composer installs.
- Test suite grown from 16 to 109 tests, including a frozen test vector generated by the real v1.0.0 code.

### Fixed

- `db-encrypt:re-encrypt` couldn't rotate keys. It decrypted and encrypted with the same key, and failed after `DB_ENCRYPT_KEY` changed.
- Retrieved models always appeared dirty, so every save re-encrypted every value, and `saveQuietly()` failed on any retrieved model. Only changed values are now written.
- Mutators ran again on save and on load, corrupting values, and accessor output was what got encrypted. The raw attribute value is now stored, so casts, mutators and accessors all work correctly.
- Boolean `false` was encrypted as an empty string and read back as empty. It's now stored as `"0"`.
- Arrays and objects without a cast caused a `TypeError`. They now throw `InvalidAttributeException`, without including the value in the message.
- Class-cast attributes such as `AsArrayObject` could be written to the model's table on save.
- A schema query ran for every encrypted property on every retrieved model. It now runs once per table per process.
- Retrieving a model ran one query per encrypted property. It now runs one query per model.
- The log identifier grew with every model processed, leaking memory in queue workers and Octane. The shared controller instance also kept the last model in memory, so the controller is no longer a singleton.
- `setModel(null)` caused a `TypeError`.
- Saving a model selected without its primary key, or encrypting one not yet saved, could write or look up rows with a null `object_id`.
- Truncated payloads raised an OpenSSL warning instead of a `DecryptionException`.
- `isSupported()` now checks cipher names case-insensitively.
- The `--model` option on `db-encrypt:re-encrypt` and `db-encrypt:prune` did nothing. It now works, and invalid classes are rejected.
- `db-encrypt:re-encrypt --batch=0` silently did nothing, and `--dry-run` didn't check that values could be decrypted.
- `db-encrypt:prune` loaded every row into memory, ran one query per row, and only supported a parent key named `id`.
- `db-encrypt:generate-key` ignored `--force`, raised a deprecation when no key was set, ignored a failed file write, and changed line endings in `.env`.
- `EncryptedAttributes::factory()` failed for package users, because its namespace was only in `autoload-dev`.
- Migrating no longer risks a class name conflict, because the migration is now anonymous.
- On MySQL and MariaDB, values too large for the `TEXT` column now throw `InvalidAttributeException` instead of possibly being truncated.

### Changed

- `Encryptor::hash()` now returns a keyed HMAC, so its output differs from v1.0 and it requires a configured key.
- `Encryptor::getInfo()` reports the new algorithms: `aes-256-gcm`, `hkdf-sha256`, `hmac-sha256` and a 12-byte IV.
- `whereEncrypted()` now throws `InvalidAttributeException` for attributes not listed in `$encryptedProperties`, rather than finding nothing.
- Failures to load or save encrypted attributes now throw `DecryptionException` or `EncryptionException`. Both extend `RuntimeException`, so existing `catch` blocks keep working.
- Encrypted values for one save are written in a single transaction.
- `DbEncryptController` is now resolved as a new instance each time, and no longer extends Laravel's routing `Controller`, which the package never declared as a dependency.
- Tests now run on in-memory SQLite. The tracked `tests/testdb.sqlite` fixture and placeholder example tests are gone.
- CI now tests PHP 8.2 to 8.5 on Laravel 12 and 13, and replaces the skipped code style step with `composer validate` and `composer audit`.
- All Composer dependencies updated, and the unused `laravel/legacy-factories` removed.
- Removed the invalid `repository` property from `composer.json`.
- README, SECURITY.md and config comments corrected to match how the package behaves.
- Added `AGENTS.md` as the shared guide for coding agents, with `CLAUDE.md` pointing to it.

### Upgrade Notes

- **No schema changes.** Existing values can still be read and searched after upgrading.
- **Rolling back isn't automatic.** v1.0 can't read values written by v1.1, so take a backup first if you might roll back.
- **Don't change `object_type` directly in the database.** Values written by v1.1 are bound to their table name, so use `db-encrypt:rename-table`.
- **If you stored output of `Encryptor::hash()` yourself**, it won't match new hashes. Use `Encryptor::hashCandidates()` during a transition.
- **If you wrote to `encrypted_attributes` directly**, use `EncryptedAttributes::payloadFor()` so values are bound to their row.

## v1.0.0 `2026-01-20` - Production Release 🚀

### Added

- **Custom Exception Classes** for better error handling and debugging
  - `EncryptionException` for encryption failures
  - `DecryptionException` for decryption failures
  - `InvalidAttributeException` for attribute configuration errors
  - `ModelNotSetException` for missing model errors
- **Facade Support** (`DbEncrypt`) for easy access to encryption methods throughout application
- **Batch Operations** for improved performance
  - `encryptBatch()` method for encrypting multiple values at once
  - `decryptBatch()` method for bulk decryption
- **Additional Security Methods**
  - `verify()` method to compare plaintext with encrypted values without full decryption
  - `isSupported()` method to check OpenSSL availability
  - `getInfo()` method to retrieve encryption configuration details
- **Artisan Commands**
  - `db-encrypt:generate-key` - Generate and set encryption keys
  - `db-encrypt:re-encrypt` - Key rotation with batch processing and dry-run support
  - `db-encrypt:prune` - Remove orphaned encrypted attributes
- **Comprehensive Test Suite**
  - Feature tests for full encryption workflow
  - Tests for `whereEncrypted` scope
  - Tests for batch operations
  - Tests for exception handling
- **GitHub Actions CI/CD** workflow for automated testing across PHP 8.2/8.3
- **SECURITY.md** with detailed security guidelines and vulnerability reporting
- **Enhanced Documentation**
  - Comprehensive README with usage examples
  - Troubleshooting guide
  - Production deployment best practices
  - Performance optimization tips
  - Monitoring and logging instructions

### Changed

- Improved error messages with more context and actionable information
- Optimized database queries with proper composite indexing
- Better logging with configurable levels (0-3)
- Updated PHPDoc blocks for better IDE support and type hints
- Cleaned up unused imports and dependencies
- Laravel 12 full support

### Fixed

- Better handling of null/empty values in encrypted attributes
- Improved exception handling in trait event listeners
- Fixed potential memory issues in batch operations
- Proper cleanup of buffer after save operations

### Security

- Enhanced key derivation with SHA-512
- Added timing-attack resistant comparison (`hash_equals`)
- Improved validation of encrypted data format
- Better isolation between encrypted attributes and table columns
- Comprehensive security documentation
